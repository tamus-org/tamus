# AGENTS.md

Руководство для ИИ-агентов и контрибьюторов, работающих в репозитории Tamus. Прочитать до изменений.

## О проекте

Tamus — настольный редактор моделей процессов IDEF0 и DFD на Tauri 2, Svelte 5 и Rust. Версия 0.1.0 находится в бете. Цель проекта — полноценный преемник Ramus с сохранением поведения и данных, а не механический перенос Java-классов.

- План развития: [docs/ROADMAP.md](docs/ROADMAP.md).
- Целевая архитектура и матрица паритета: [docs/TAURI_SVELTE_PROJECT.md](docs/TAURI_SVELTE_PROJECT.md).
- Текущее поведение редактора: [docs/IMPLEMENTED_IDEF0.md](docs/IMPLEMENTED_IDEF0.md), [docs/DFD_AND_APPEARANCE.md](docs/DFD_AND_APPEARANCE.md), [docs/I18N.md](docs/I18N.md).
- Пользовательское описание: [README.ru.md](README.ru.md), [README.md](README.md).

## Команды

Все команды выполняются из `tamus-app/`. Используется npm (`packageManager: npm@9.2.0`), не pnpm и не yarn. Требуется Node.js 20.19+; для desktop — stable Rust и системные зависимости Tauri 2.

| Команда                | Назначение                                                    |
| ---------------------- | ------------------------------------------------------------- |
| `npm ci`               | Установка зависимостей по lock-файлу                          |
| `npm run dev`          | Vite на фиксированном порту 1420                              |
| `npm run tauri dev`    | Настольное приложение; Vite запускается автоматически         |
| `npm run build`        | Статический frontend в `build/`                               |
| `npm run tauri build`  | Нативная сборка и установочные пакеты                         |
| `npm run check`        | `svelte-check` и проверка TypeScript                          |
| `npm test`             | Node-тесты модели проекта и локализации                       |
| `npm run format`       | Prettier для `src`, `scripts`, `tests`, README и конфигурации |
| `npm run format:check` | Проверка форматирования                                       |
| `npm run test:ui`      | Базовый браузерный smoke                                      |
| `npm run test:idef0`   | Сценарий IDEF0                                                |
| `npm run test:ramus`   | Сценарий классификаторов и рабочих процессов                  |
| `npm run test:shell`   | Оболочка, DFD, темы, сохранение                               |
| `npm run test:i18n`    | Локализация                                                   |

Ядро проверяется отдельно, без GTK/WebKit:

```bash
cargo test --manifest-path src-tauri/crates/tamus-core/Cargo.toml
cargo clippy --manifest-path src-tauri/crates/tamus-core/Cargo.toml --all-targets -- -D warnings
```

Браузерные сценарии требуют запущенного `npm run dev` в другом терминале. Переменные: `TAMUS_URL` — адрес сервера, `PLAYWRIGHT_CHANNEL=msedge` — установленный Edge, `PLAYWRIGHT_MODULE` — внешний Playwright. Скриншоты пишутся в `.artifacts/` и не коммитятся.

## Определение готовности задачи

Перед завершением работы выполнить применимые проверки:

1. `npm run check`
2. `npm test`
3. `npm run format:check`
4. `npm run build`
5. Для изменений в `tamus-core`: `cargo test` и `cargo clippy -- -D warnings`.
6. Для изменений UI или поведения: соответствующий браузерный сценарий при запущенном dev-сервере.

Нельзя утверждать, что нативное приложение работает, на основании frontend-сборки, браузерных тестов или тестов Rust. Desktop-поведение подтверждается только сборкой и запуском на целевой ОС; иначе так и указывать: «desktop не проверен».

## Архитектурные правила

### Два исполнителя одного контракта

- В desktop-режиме авторитетно состояние Rust; в браузерном preview используется reducer в `src/lib/domain/project.ts`.
- Любая новая команда, правило валидации или инвариант реализуются в обоих исполнителях и покрываются общим fixture из `fixtures/`.
- Контракт DTO — `camelCase` на границе; в Rust используется `#[serde(rename_all = "camelCase")]` и, как принято в проекте, `deny_unknown_fields` для строгих структур.
- `tamus-core` не должен зависеть от Tauri, GTK или WebKit.
- UI общается с ядром через `src/lib/services/project-client.ts`. Прямой `invoke` допустим только для управления окном, как в `+page.svelte`.
- Команда должна быть атомарной и попадать в историю как одно изменение; лимит истории — 100 шагов. Не обходить revision-проверки и не писать файлы из компонентов напрямую.

### Формат проекта и совместимость

- Текущий формат — `.tamus.json`, `schemaVersion: 1`. Старые файлы должны открываться; неизвестные поля нельзя молча терять.
- Изменение схемы требует миграции, обновления валидации в TypeScript и Rust, fixtures и документации.
- Целевой формат и правила миграции описаны в роадмапе; не менять формат без ADR и согласованной миграции.
- Импорт Ramus должен диагностировать неподдержанное, а не отбрасывать данные.
- Fixtures — часть контракта. Не удалять и не ослаблять их без замены эквивалентным покрытием.

### Интерфейс

- Используется Svelte 5 с рунами (`$state`, `$derived`, `$effect`, `$props`).
- Стили опираются на CSS-переменные из `src/app.css`. Новые цвета и отступы оформлять через существующие токены и проверять в обеих темах.
- Любая новая интерфейсная строка добавляется в `src/lib/i18n/catalog.ts` и выводится через `$t`; счётчики — через `$count`/`formatCount`, а не склейкой числа с окончанием.
- Русские исходные сообщения служат ключами. Пользовательские названия, описания и подписи потоков не переводятся.
- Пользовательские данные выводятся обычным текстом Svelte; `{@html}` для них не использовать.
- Не добавлять удалённые шрифты, скрипты и стили: CSP в `tauri.conf.json` это запрещает.

### Безопасность

- Не расширять capabilities и permissions без необходимости; новые команды добавляются в `permissions/project.toml` осознанно.
- Не логировать секреты и содержимое пользовательских файлов.
- Не отключать CSP и не ослаблять ограничения ради удобства разработки.

## Стиль кода

- Prettier: одинарные кавычки, ширина 100, отступ 2, плагин Svelte. Запускать `npm run format` перед проверкой.
- TypeScript строгий; не подавлять ошибки через `any` или `@ts-ignore` без причины.
- Комментарии — только там, где неочевиден инвариант или причина решения.
- Сообщения об ошибках и названия сущностей — в стиле окружающего кода.
- Не редактировать вручную сгенерированные файлы (`src-tauri/gen/`, `src-tauri/permissions/autogenerated/`), иконки и lock-файлы. Lock-файлы меняются только через npm/cargo.
- Порт 1420 фиксирован (`strictPort`); не менять его и не запускать второй dev-сервер.

## Git и оформление изменений

- Не коммитить без явного запроса пользователя.
- Перед коммитом просматривать `git status` и `git diff`; не включать артефакты, скриншоты, `node_modules`, `target` и пользовательские `*.tamus.json`.
- Сообщение коммита — краткое, в стиле репозитория (`feat:`, `fix:`, `docs:`).
- Лицензия проекта — GNU GPL-3.0 ([LICENSE](LICENSE)).

## Ограничения среды

- Репозиторий разрабатывается и проверяется на Windows; команды приведены для PowerShell.
- Нативная сборка Linux требует GTK/WebKit/DBus development packages и может быть недоступна в текущем окружении.
- Браузерные тесты не заменяют проверку Tauri WebView, нативных диалогов и печати.
