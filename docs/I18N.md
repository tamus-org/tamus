# Локализация интерфейса

Tamus поддерживает русский (`ru`) и английский (`en`). Язык выбирается в «Настройки → Язык интерфейса» / «Settings → Interface language» и применяется без перезагрузки. По умолчанию используется русский. Выбор хранится отдельно от проекта в localStorage `tamus:locale:v1`; отключённое хранилище не мешает переключению в текущем сеансе.

## Область перевода

Переведены меню, панели, свойства, настройки, справка, диалоги, подписи и подсказки инструментов IDEF0/DFD, ARIA-имена, верхний и нижний штампы, статусы и известные ошибки валидации. Числа и формы счётчиков используют `Intl.NumberFormat` и `Intl.PluralRules`. Атрибут `html.lang` обновляется вместе с языком. В Tauri текущая локаль передаётся командам открытия/сохранения для заголовков и фильтра файлового диалога; собственные системные кнопки диалога зависят от ОС.

Пользовательские названия, описания, подписи потоков и заполненные поля штампа не переводятся. Учебный проект сохраняет исходные русские имена. Переключение языка не меняет JSON, dirty-state или undo/redo и не сбрасывает черновик инспектора.

Новые элементы и блоки получают начальные имена на текущем языке. Декомпозиция передаёт `blockNamePrefix` в команду `decomposeBlock`: английские `Function` / `Process` или прежнее русское `Функция`. Это данные создаваемых объектов, а не локаль проекта. Если параметр отсутствует, старые команды продолжают создавать имена «Функция N». Контракт одинаков в TypeScript и Rust. Уже созданные имена не меняются при переключении языка.

Технические обозначения I/C/O/M, A-0/A0 и числовые коды DFD сохраняются. Служебные обозначения «Контекст» и «ВЕРХ» в рисунке и навигации показываются как Context / TOP без изменения сохранённой структуры.

## Код

- `src/lib/i18n/catalog.ts` — английский словарь, подстановка параметров, форматирование счётчиков и известных диагностик. Русские исходные сообщения служат ключами; отсутствующий перевод возвращает исходное сообщение.
- `src/lib/i18n/index.ts` — реактивные Svelte stores `locale`, `t`, `count`, переключение и восстановление настройки. Компоненты используют `$t(message, params)` и `$count(noun, number)`.
- `src/lib/services/project-client.ts` — передача локали нативным диалогам.

Динамические имена передаются отдельными параметрами, например `$t('В проекте «{name}» есть несохранённые изменения.', { name })`. Сообщения выводятся обычным текстом Svelte, без `{@html}`. Значения `$&`, фигурные скобки и HTML внутри имени остаются буквальными данными. Динамические причины файловых ошибок сохраняются вместе с переведённым префиксом.

Добавляя интерфейсную строку, добавьте её английское значение в `catalog.ts` и используйте `$t`. Предложения с параметрами хранятся целиком, чтобы перевод мог менять порядок слов. Названия объектов проекта не следует пропускать через словарь. Счётчики добавляются через `formatCount`, а не объединением числа с фиксированным русским окончанием.

## Проверки

`npm test` включает проверку покрытия статических UI-ключей, параметров переводов, отсутствия непереведённого текста в разметке, интерполяции и склонений. `fixtures/localized-decomposition.json` проверяется TypeScript и Rust, включая сохранность исходных имён и отклонение неверного префикса.

При запущенном Vite: `npm run test:i18n`. Сценарий проверяет переключение и сохранение языка, ARIA/штампы/меню, сохранность черновика и JSON, английские свойства и выбор объектов, имена новых элементов, DFD, переведённую валидацию и имена декомпозиции. Скриншот — `.artifacts/english-workspace.png`. Прежние браузерные сценарии проверяют русский интерфейс.

Нативные диалоги подготовлены в коде; их фактический запуск требует desktop-сборки. Текущие браузерные проверки и тесты Rust-ядра не заменяют её проверку.
