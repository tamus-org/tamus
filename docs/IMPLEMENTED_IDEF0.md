# Реализованный вертикальный срез IDEF0

Расположение приложения: `tamus-app`. Это описание текущей реализации, а не всей целевой спецификации из `TAURI_SVELTE_PROJECT.md`.

## Работа в редакторе

Новая модель начинается с контекстного листа A-0 и одного функционального блока. Ctrl/⌘+щелчок по блоку открывает его декомпозицию. Если её нет, открывается диалог шаблона и числа работ (2–20); лист и функции создаются одной командой. Двойной щелчок открывает свойства блока. «В блок» работает для выделенной функции, «Родитель» возвращает на уровень выше. Переходы доступны также через дерево и цепочку предков. Номера уровней рассчитываются от положения функции в родителе: A-0 → A0 → A1 → A11.

«Стрелка» включает построение в два щелчка. Начало — выход блока справа или граница I/C/M. Конец — вход слева, управление сверху, механизм снизу другого блока или выходная граница O. До завершения показывается предварительная линия; Escape отменяет построение. Название и роль целевого присоединения редактируются в свойствах. Линию можно выделить щелчком или клавиатурой. Трасса автоматически огибает блоки; перемещение блока пересчитывает её.

Дочерний лист показывает I/C/O/M-интерфейсы блока-владельца с именами родительских стрелок. Щелчок по такому интерфейсу позволяет продолжить стрелку к дочерней функции (для O — сначала выбрать выход функции). Пока стрелка не продолжена, интерфейс остаётся виден как неподключённый. Имя связанной дочерней стрелки наследуется. Переименование, смена роли и удаление родительской стрелки обновляют связанные уровни в той же транзакции и undo-группе.

Номера блоков — `A1`, `A22` и т. п. Блок без декомпозиции помечается косой чертой в левом верхнем углу; у блока с декомпозицией маркера нет. В поле «Контекст» рисуется мини-схема родительского слоя с закрашенным текущим блоком.

## Данные и инварианты

Временный формат остаётся `.tamus.json`, schemaVersion 1. Старые файлы без новых полей открываются; старые окончания между блоками трактуются как O → I.

- `Model.parentBlockId?: string` указывает на блок-владелец. В `models` хранятся все листы; корни — записи без владельца. Один блок имеет не более одной декомпозиции. Проверяются существование владельца и отсутствие циклов.
- `Model.pageWidth?` / `pageHeight?` задают размер листа. Импорт Ramus вычисляет их по рамке диаграммы, поэтому блоки и отступы сохраняют исходные пропорции; без полей используется прежний лист 1050×742.
- `Flow.sourceId` / `targetId` принимают ID блока или `null` для границы. Между двумя границами и внутри одного блока соединение пока запрещено.
- `sourceSide` / `targetSide`: `left`, `top`, `right`, `bottom`; `sourcePosition` / `targetPosition` — относительная координата вдоль стороны, 0.05…0.95.
- `Block.fontName?` / `fontSize?` / `fontStyle?` — необязательный шрифт блока. При импорте Ramus размер переносится из `F_FONT` в пунктах и пересчитывается в CSS-пиксели при отрисовке; старые проекты без полей используют прежний шрифт.
- `parentFlowId?: string` связывает граничную стрелку с интерфейсом родительского блока. Нельзя ссылаться на произвольный поток другой диаграммы.
- `Flow.waypoints?: { x, y }[]` хранит ручные изгибы стрелки (до 128 точек), `Flow.labelX/labelY` — положение подписи, `hideLabel` скрывает дубль подписи ветки. Непустой массив включает ручную трассу; пустой или отсутствующий — автоматическую трассу Tamus. Все сегменты принудительно горизонтальны или вертикальны (90°), включая импорт и экспорт. Перетаскивание линии или подписи сохраняется одной командой `updateFlow`; при импорте Ramus непустые точки сектора, направление обхода и позиция текста переносятся сюда. Выделенный блок подсвечивает связанные стрелки жирным.
- `decomposeBlock` выполняется в Rust как одна атомарная команда. Браузерный reducer имеет тот же контракт. Общий сценарий `fixtures/idef0-scenario.json` проверяется обоими исполнителями.
- Удаление блока с декомпозицией и диаграммы с дочерними уровнями отклоняется: сначала нужно удалить дочерние листы. Undo восстанавливает данные и интерфейсы целиком.

## Границы реализации

Пока отсутствуют развилки/слияния общих потоков, туннели, ручная правка изгибов и точек присоединения, полный контроль балансировки ICOM. Новый независимый граничный поток внутри дочерней диаграммы ещё не создаёт встречный интерфейс у родителя; это не следует считать реализованным туннелем. Редактор допускает рабочие, ещё не полностью соединённые диаграммы. Исходный учебный лист A0 сохранён для совместимости; новые модели создаются с A-0.

## Проверки

`npm run check`, `npm test`, `npm run build`, `npm run test:ui`, `npm run test:idef0`; отдельно тесты и clippy crate `tamus-core`. Браузерные проверки требуют запущенного Vite. Нативная сборка host по-прежнему зависит от установки системных GTK/WebKit/DBus development packages.

Режимы, свойства, дерево функций и присоединённые объекты описаны в [сверке с документацией Ramus](../../docs/19-tamus-implementation-status.md). `npm run test:ramus` проверяет этот сценарий отдельно.

DFD, основной/расширенный режимы, заголовок окна и цвета описаны отдельно в [DFD_AND_APPEARANCE.md](DFD_AND_APPEARANCE.md).

## Совместимость с Ramus (.rsf)

Импорт и экспорт доступны в меню «Файл». Поддерживается обмен моделями IDEF0/DFD: модели и декомпозиции, функциональные блоки и их геометрия, потоки и границы I/C/O/M, классификаторы и присоединённые к потокам объекты, а также штампы (автор, даты, замечания, номер листа).

- Формат — ZIP-архив Ramus с XML-таблицами (`data/elements.xml`, `data/attributes.xml`, `data/Core/*`, `data/IDEF0/*`). Экспорт создаёт самостоятельный `.rsf`.
- После импорта показывается отчёт: число моделей, блоков, связей, классификаторов и элементов; неизвестные таблицы перечисляются, а не отбрасываются молча.
- DFD: типы блоков Ramus 1001/1002 отображаются во внешние сущности и хранилища; тип декомпозиции 1 включает DFD.
- Стороны I/C/O/M и точки крепления берутся из Ramus (`BORDER_TYPE` и координаты сектора): входы приходят слева, управление сверху, механизмы снизу, выходы справа.
- Трассы стрелок переносятся по точкам секторов с учётом направления обхода; рамка Ramus (~7 px) вычитается при импорте и возвращается при экспорте, поэтому блоки и изгибы сохраняют исходное положение. Служебные квадраты границы листа показываются только в режиме «Стрелка», в режиме выбора их нет.
- Ограничения: YAML schema 4, вложения, история, отчёты, матрицы, туннели, развилки и точная cross-level геометрия Ramus пока не переносятся. Экспорт проверен fixture-тестами и round-trip, но не подтверждён открытием в настольном Ramus.
